# Batch manifest

Use this when one assignment covers multiple lessons. Keep it local with other
working notes. Create one row per candidate before researching or drafting.

| Slug | Reader decision | Example | Nearest lesson and distinction | Diagram argument | Evidence candidates | Review state |
| --- | --- | --- | --- | --- | --- | --- |
|  |  |  |  |  |  |  |

For each candidate, record:

- **Reader problem and takeaway:** what specific decision the reader can make
  after the lesson.
- **Example and failure:** a distinct concrete situation, including what can go
  wrong and what the responsible system should do next.
- **Existing coverage:** the nearest lesson and why this proposal adds a new
  capability rather than restating its conclusion.
- **Evidence:** at least three candidate primary sources, plus a counterpoint
  source for contested topics. The claim ledger remains per lesson.
- **Diagram argument:** one claim and a reading order that fit the lesson.
- **Relationships:** prerequisite and related lesson slugs, with a reason for
  each link.
- **Review state:** brief, research, draft, self-review, independent review,
  verification, and publication status. Never mark review complete by inference.

Before drafting, compare all rows. Merge or drop candidates that lead to the
same reader decision, rely on the same example without a distinct mechanism, or
repeat an existing lesson. Preserve independently valuable items when another
row is blocked for missing evidence. Record that decision and its reason.

The manifest authorizes only the work stated in the assignment. A scheduled
writing task does not by itself authorize publishing, pushing, or changing site
settings.
