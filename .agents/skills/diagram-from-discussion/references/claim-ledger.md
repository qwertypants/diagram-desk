# Claim ledger

Track every claim a reader could reasonably challenge. Keep the ledger local
(for example under `tasks/`); it is working evidence, not published content.

| Claim | Source | Date or version | Tier | Confidence | Caveat |
| --- | --- | --- | --- | --- | --- |
|  |  |  |  |  |  |

Include:

- numbers, percentages, prices, latency, and token counts;
- comparisons and superlatives ("faster", "first", "state of the art");
- benchmark results, with model, harness, task set, date, and metric;
- security properties and failure modes;
- protocol behavior and versioned specifications;
- claims about what a vendor, model, or framework does.

Prefer the exact section or version that supports the claim. If the source is a
summary, follow it to the primary source. If a claim cannot be checked, narrow it
or remove it.

Before drafting, every nontrivial claim should have a source and a confidence
note. Fast-moving claims need an explicit "As of <Month Year>" line in the
article.
