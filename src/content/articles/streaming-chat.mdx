A stream can make an answer feel immediate while its final correctness is still unknown. Treat partial and complete states differently.

## The problem

A chat interface should stay responsive during a long model response.

## Read the architecture

Follow one chunk from provider to UI, then compare that path with completion and validation.

<DiagramEmbed slug="streaming-chat" title={'Stream AI in chat'} />

### Walk through it

#### 1. Request

The UI submits a message through the backend and orchestrator to the provider.

#### 2. Chunks

Each chunk returns through the orchestrator and backend. SSE and WebSocket are alternative transports, not interchangeable protocol names.

#### 3. Completion

The orchestrator validates the complete result before final metadata reaches the UI. A partial reply is not yet final.

## Design decisions

- Keep cancellation and provider errors visible to the client.

## Failure modes

- A disconnected stream can leave a partial answer.
- Validation after completion cannot retract tokens already displayed.

## Key takeaways

- Streaming improves perceived responsiveness, not model correctness.
