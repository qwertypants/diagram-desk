Autonomy is useful when the system can inspect its work, ask for help, and stop. Tool design and feedback matter as much as the model.

## The problem

An agent can take actions without making its reasoning or outcomes understandable.

## Read the architecture

Read the choices in order: understandable control, observed feedback, and evidence that the use case fits.

<DiagramEmbed slug="effective-agent-principles" title={'Effective Agents: Design Principles and Practice'} />

### Walk through it

#### 1. Keep control understandable

Begin with a simple design. Expose meaningful steps and design, document, and test tools.

#### 2. Use feedback

Evaluate environment observations and retain human checkpoints.

#### 3. Check fit

Support retrieves context and performs permitted actions; coding uses test feedback and review. Other use cases need the same success and oversight criteria.

## Design decisions

- Increase autonomy only where observations let the system assess progress.

## Failure modes

- More agents and tools can increase compounding errors.

## Key takeaways

- Tool design is part of product reliability.
