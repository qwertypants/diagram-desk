Composition helps when one call cannot do the whole job. Each pattern places control, aggregation, and feedback in a different place.

## The problem

A single model call is insufficient, but unrestricted autonomy is unnecessary.

## Read the architecture

Compare the lanes as alternatives rather than as stages of one pipeline.

### Walk through it

#### 1. Chaining and routing

Chaining passes work through ordered calls and optional gates. Routing classifies input before choosing specialized work.

#### 2. Parallelization

Sectioning assigns different subtasks. Voting repeats the same task. Each requires an aggregation step.

#### 3. Orchestration and refinement

Orchestrator-workers decomposes tasks dynamically and synthesizes worker results. Evaluator-optimizer feeds critique back to the generator until accepted.

## Design decisions

- Use separate visual lanes so independent patterns cannot be mistaken for one runtime pipeline.
- Give a refinement loop a stopping budget.

## Failure modes

- Voting can repeat correlated errors.
- A judge can prefer fluent but incorrect output.

## Key takeaways

- Parallel sectioning and repeated voting solve different problems.
