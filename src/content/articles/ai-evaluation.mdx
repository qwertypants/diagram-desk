A good evaluation loop begins with a real user task, follows the evidence of a failure, and tests a proposed change before release.

## The problem

A prompt or model update can improve average scores while breaking important user tasks.

## Read the architecture

Follow the production response into sampled cases, then compare each grading path before the release decision.

<DiagramEmbed slug="ai-evaluation" title={'AI System with evaluation'} />

### Walk through it

#### 1. Observe

Production traffic passes through the AI application and model. Responses and request context are recorded under an explicit data policy.

#### 2. Grade

Sampled production cases and a golden dataset feed deterministic checks, an LLM judge, and human review. Their results reach a dashboard.

#### 3. Decide

A detected regression sends prompt, model, or retrieval changes back through evaluation. A passing decision permits deployment.

## Design decisions

- Use deterministic checks for properties that have a clear exact answer.
- Calibrate model judges against human review and inspect individual failures.

## Failure modes

- An aggregate score can conceal a severe regression in a small segment.
- Production logs can contain sensitive data; sampling requires redaction and retention policies.

## Key takeaways

- A release decision needs task-specific acceptance criteria.
