Application code should choose the next step when the process is known. A model-led agent can help when an investigation must adapt to what it discovers. Start by checking whether a single model call with the right context already solves the task.

For example, drafting a support reply from supplied documentation may need one call. Classifying a ticket, retrieving its documentation, and drafting a reply can follow a fixed workflow. Investigating a missing export may need a changing sequence of job-status and delivery lookups.

Follow **Start simple** through the two questions in the top lane. Then compare the workflow and agent paths as they converge on **Measure outcomes**.

**Predictable process** and **Flexibility and cost** describe different consequences of control. Neither establishes that an approach is better for your task. Compare actual resolutions, response time, and resource use on the same cases.

The one-call branch ends early in this drawing, but it still needs evaluation as the baseline. **Better outcomes?** sends an unsuccessful comparison back to the start. **Keep it simple** means retain the least complicated approach that works, including an agent if its flexibility earns the cost.

An agent still needs application-enforced permissions and stopping limits. Choosing actions and authorizing them are separate responsibilities.
