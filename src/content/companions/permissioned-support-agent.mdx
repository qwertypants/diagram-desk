The model can propose a refund. Application policy decides whether the proposal is permitted, a human approves the specific consequential action, and the application checks what the external service actually did.

For a hypothetical $40 refund on order 4821, approval should identify that order and amount. An approval for $40 does not authorize a later $80 proposal. A forbidden operation remains forbidden even if someone clicks an approval button.

**Execute with key** uses a stable operation identifier so a supported retry can refer to the same logical refund. A timeout is an unknown outcome: the provider may have applied the refund before the reply was lost. **Reconcile outcome** looks up the original operation before **Check receipt**.

Success requires a receipt matching the approved order, amount, and outcome. **More work** can return to another proposal, but **Budget exhausted** limits investigation. If the outcome stays uncertain, the application must preserve and report that uncertainty; this chart does not show every intervention path.

Read-only work can take the policy's allowed branch. The human-consent branch exists for this example's refund policy, not as a requirement for every tool call.
