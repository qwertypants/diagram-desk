# API Contract

Binding contract between the UI worker and the API worker. Both sides build
against this document; neither may change it without a controller ruling.

## Transport

One Node server binds `127.0.0.1` (never `0.0.0.0`) and serves both the built
static site and the JSON API below.

- Base URL: `http://127.0.0.1:${PORT}`, default `PORT=4317`
- All API paths are under `/api`
- Requests and responses are `application/json; charset=utf-8`, except the
  `204` response which has no body
- Every error response body is `{"error": "<human readable message>"}` with a
  non-2xx status

## Diagram object

```json
{
  "id": "0f1c2d3e-4a5b-6c7d-8e9f-0a1b2c3d4e5f",
  "title": "Order flow",
  "source": "flowchart TD\n  A[Start] --> B[End]",
  "createdAt": "2026-10-02T09:15:00.000Z",
  "updatedAt": "2026-10-02T09:15:00.000Z"
}
```

- `id` — UUID string, generated by the server, immutable
- `title` — non-empty string after trimming, 1..200 characters
- `source` — non-empty string after trimming, 1..100000 characters
- `createdAt` / `updatedAt` — ISO 8601 UTC strings with milliseconds

## Endpoints

### `GET /api/diagrams?q=<term>`

`q` is optional. When present and non-blank, only diagrams whose **title**
contains `q` case-insensitively are returned. Matched on title only.

Response `200`:

```json
{"diagrams": [ <diagram>, ... ]}
```

Ordering is always `updatedAt` descending, ties broken by title ascending, and
applies to both the filtered and unfiltered case.

### `GET /api/diagrams/:id`

- `200` with the `<diagram>` object
- `404` `{"error": "Diagram not found"}` for an unknown or malformed id

### `POST /api/diagrams`

Request body: `{"title": "...", "source": "..."}`

- `201` with the created `<diagram>` object
- `400` `{"error": "..."}` when the body is not valid JSON, is not an object,
  `title` is missing/blank/not a string/over 200 chars, or `source` is
  missing/blank/not a string/over 100000 chars
- `405` `{"error": "..."}` for a non-`POST` method on this path

Unknown extra fields in the request body are ignored, not rejected.

### `PUT /api/diagrams/:id`

Request body: `{"title": "...", "source": "..."}` — same validation as `POST`,
and `title` and `source` are both required on every update (partial updates are
not supported in this version).

- `200` with the updated `<diagram>` object
- `400` for invalid JSON or invalid `title`/`source`
- `404` `{"error": "Diagram not found"}` for an unknown id
- `405` for a non-`PUT` method on this path

`updatedAt` changes on every successful update; `createdAt` does not.

### `DELETE /api/diagrams/:id`

- `204` with no body
- `404` `{"error": "Diagram not found"}` for an unknown id
- `405` for a non-`DELETE` method on this path

Deletion is permanent. There is no undo endpoint.

### Unknown paths

Any `/api/...` path that is not one of the above gets `404`
`{"error": "Not found"}`.

## Storage

- SQLite file at `data/diagrams.sqlite` relative to the repository root, so it
  is git-ignored
- The path is overridable with the `DIAGRAMS_DB` environment variable so tests
  can point at a temporary file
- The table and any index are created on server start if missing, so a fresh
  clone with no database file works
- Mermaid source is stored as written, not normalized

## Persistence requirement

A diagram written before a server restart must still be returned by
`GET /api/diagrams` and `GET /api/diagrams/:id` after the restart. Writes must
be committed before the response is sent.
